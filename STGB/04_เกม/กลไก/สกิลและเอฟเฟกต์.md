# STGB — กลไกสกิลและเอฟเฟกต์

## จุดประสงค์

เอกสารนี้เก็บข้อเท็จจริงเกี่ยวกับกลไกของสกิลและเอฟเฟกต์ที่ต้นฉบับหรือหลักฐานที่เชื่อถือได้ระบุไว้อย่างชัดเจน

ข้อมูลที่สามารถเก็บ ได้แก่

* วิธีเปิดใช้
* เงื่อนไขการเปิดใช้
* เป้าหมาย
* ระยะ
* พื้นที่ผล
* ระยะเวลา
* คูลดาวน์
* ทรัพยากรที่ใช้
* ผลหลัก
* ผลรอง
* สถานะที่เกิดขึ้น
* วิธีลบล้าง
* วิธีต้านทาน
* การซ้อนทับ
* ปฏิสัมพันธ์กับสกิลอื่น
* ข้อยกเว้น
* ข้อจำกัด
* ตัวเลขที่ต้นฉบับระบุ
* ความแตกต่างระหว่างสกิลกับเอฟเฟกต์

ชื่อไทยและสถานะชื่อให้ยึด:

`../สกิล.md`

## สถานะข้อมูลปัจจุบัน

ไฟล์ต้นทางที่มีอยู่เก็บเพียงชื่อสกิล ประเภท และสถานะชื่อ โดยไม่ได้เก็บรายละเอียดกลไก

ดังนั้น ณ ขอบเขตตอนที่ 395:

* ยังไม่มีรายการกลไกที่ยืนยันเพียงพอ
* ห้ามเติมผลของสกิลจากความหมายของชื่อ
* ห้ามเติมกลไกจากความรู้ทั่วไปของเกม
* ห้ามคาดเดากลไกจากเหตุการณ์ที่จำได้โดยไม่มีข้อความหลักฐาน
* ห้ามใช้คำแปลชื่อเป็นหลักฐานว่ากลไกทำงานอย่างไร
* รายการที่คลุมเครือระหว่างสกิลกับเอฟเฟกต์ให้เก็บไว้ในส่วน `รอตรวจประเภท`

# หลักการบันทึกกลไก

## หนึ่งข้อเท็จจริงต่อหนึ่งรายการ

แต่ละข้อเท็จจริงต้องระบุ:

* สกิลหรือเอฟเฟกต์ที่เกี่ยวข้อง
* ข้อความกลไก
* ขอบเขตที่กลไกใช้ได้
* แหล่งหลักฐาน
* ช่วงตอน
* ระดับความมั่นใจ
* ข้อจำกัดหรือข้อยกเว้น
* สถานะการตรวจสอบ

ห้ามรวมหลายข้อสรุปไว้ในประโยคเดียว หากหลักฐานยืนยันเพียงบางส่วน

## แยกข้อเท็จจริงออกจากการตีความ

ใช้ช่องต่อไปนี้แยกกัน:

| ช่อง | ใช้เก็บ |
| ------------- | --------------------------------------- |
| ข้อเท็จจริง | สิ่งที่ข้อความระบุหรือแสดงให้เห็นโดยตรง |
| การตีความ | ข้อสรุปที่เกิดจากการเชื่อมโยงข้อมูล |
| ยังไม่ทราบ | ข้อมูลที่หลักฐานยังไม่ตอบ |
| ข้อห้ามอนุมาน | ข้อสรุปที่ไม่ควรสร้างจากข้อมูลปัจจุบัน |

การตีความห้ามได้รับสถานะ `ยืนยันแล้ว` จนกว่าจะมีหลักฐานโดยตรงรองรับ

## รักษาตัวเลข

เมื่อกลไกมีตัวเลข ต้องรักษา:

* จำนวน
* หน่วย
* ระยะเวลา
* ระยะทาง
* เปอร์เซ็นต์
* จำนวนครั้ง
* ลำดับ
* เงื่อนไขเปรียบเทียบ
* ค่าสูงสุดและค่าต่ำสุด

ห้าม:

* ปัดเลข
* เปลี่ยนหน่วยโดยไม่เก็บค่าต้นฉบับ
* ใช้คำกว้างแทนตัวเลข
* เติมตัวเลขจากความทรงจำ
* รวมค่าจากคนละช่วงตอนเข้าด้วยกัน

## รักษาระดับความแน่นอน

ต้องแยกคำประเภท:

* ทำให้
* สามารถทำให้
* มีโอกาสทำให้
* อาจทำให้
* ป้องกัน
* ลด
* ต้านทาน
* ยกเลิก
* ไม่ได้รับผล
* ยังไม่ทราบ

ห้ามทำให้ผลที่มีโอกาสเกิดกลายเป็นผลที่เกิดแน่นอน

# สถานะการตรวจสอบ

| สถานะ | ความหมาย |
| ------------------ | ----------------------------------------- |
| ยืนยันแล้ว | มีข้อความหรือหลักฐานตรงรองรับ |
| ยืนยันบางส่วน | ยืนยันได้เพียงบางองค์ประกอบของกลไก |
| สังเกตจากเหตุการณ์ | เห็นผลในฉาก แต่ยังไม่มีคำอธิบายระบบโดยตรง |
| รอตรวจต้นฉบับ | ต้องตรวจข้อความต้นฉบับ |
| ข้อมูลขัดแย้ง | หลักฐานสองแหล่งให้ข้อมูลต่างกัน |
| ไม่ทราบ | ยังไม่มีข้อมูลรองรับ |
| ยกเลิก | เคยบันทึกไว้แต่ภายหลังพบว่าไม่ถูกต้อง |

# ทะเบียนกลไกที่ยืนยันแล้ว

ยังไม่มีรายการกลไกที่ยืนยันเพียงพอจากไฟล์ต้นทางปัจจุบัน

เมื่อมีหลักฐานใหม่ ให้เพิ่มในรูปแบบ:

```md id="157u8v"
## ชื่อสกิลหรือเอฟเฟกต์

- ID:
- ชื่อไทย:
- ประเภท:
- ช่วงตอน:
- สถานะ:

### การเปิดใช้

### เป้าหมาย

### ระยะและพื้นที่ผล

### ระยะเวลา

### ทรัพยากรและคูลดาวน์

### ผลหลัก

### ผลรอง

### การต้านทานและลบล้าง

### การซ้อนทับ

### ปฏิสัมพันธ์กับสกิลอื่น

### ข้อจำกัดและข้อยกเว้น

### สิ่งที่ยังไม่ทราบ

### หลักฐาน
```

ห้ามเพิ่มหัวข้อที่ไม่มีข้อมูลด้วยการคาดเดา ให้ใส่ `ไม่ทราบ` หรือเว้นหัวข้อนั้นไว้

# รายการรอตรวจประเภท

## Evolved Armor / Evolved Shell / Evolved Hide

### รายการที่เกี่ยวข้อง

* `skill.evolved_armor`

  * อังกฤษ: `Evolved Armor`
  * รูปอังกฤษอื่น: `Evolved Shell`
  * ไทย: `[เกราะวิวัฒน์]`
  * ประเภทปัจจุบัน: สกิล
  * สถานะชื่อ: ชั่วคราว

* `skill.evolved_hide`

  * อังกฤษ: `Evolved Hide`
  * ไทย: `[หนังวิวัฒน์]`
  * ประเภทปัจจุบัน: สกิล/เอฟเฟกต์
  * สถานะ: รอตรวจ

### สิ่งที่ยืนยันได้

* มีชื่ออังกฤษอย่างน้อยสามรูปในฐานข้อมูลเดิม
* `Evolved Armor` และ `Evolved Shell` ถูกจัดรวมไว้ในรายการเดียว
* `Evolved Hide` ถูกบันทึกแยกต่างหาก
* ประเภทของ `Evolved Hide` ยังไม่ชัดว่าเป็นสกิลหรือเอฟเฟกต์
* ฐานข้อมูลเดิมระบุว่าต้องตรวจความสัมพันธ์ระหว่างรายการเหล่านี้

### สิ่งที่ยังไม่ทราบ

* ทั้งสามชื่อหมายถึงกลไกเดียวกันหรือไม่
* `Evolved Shell` เป็นรูปแปลต่างแหล่งของ `Evolved Armor` หรือไม่
* `Evolved Hide` เป็นสกิลแยกหรือผลที่เกิดจากสกิลอื่น
* ผลของแต่ละรายการคืออะไร
* มีเงื่อนไขการเปิดใช้หรือไม่
* มีระยะเวลาหรือคูลดาวน์หรือไม่
* สามารถใช้ร่วมกันหรือซ้อนกันได้หรือไม่
* ชื่อไทย `[เกราะวิวัฒน์]` และ `[หนังวิวัฒน์]` ต้องแยกใช้ตามกลไกหรือไม่

### ข้อห้ามระหว่างรอตรวจ

* ห้ามรวม `skill.evolved_armor` กับ `skill.evolved_hide`
* ห้ามระบุว่าทั้งสองเป็นสกิลเดียวกัน
* ห้ามระบุว่า `Evolved Hide` เป็นผลติดตัว
* ห้ามระบุว่าช่วยเพิ่มพลังป้องกัน
* ห้ามระบุว่ามีการเปลี่ยนรูปลักษณ์
* ห้ามกำหนดระยะเวลา คูลดาวน์ หรือตัวเลข
* ห้ามเปลี่ยนชื่อไทยรายการใดรายการหนึ่งเพื่อให้เหมือนกัน
* ห้ามลบรูปอังกฤษ `Evolved Shell`

### หลักฐานที่ต้องหาเพิ่ม

* ข้อความระบบเมื่อได้รับหรือเปิดใช้
* ข้อความอธิบายสกิล
* ข้อความที่แสดงชื่อก่อนและหลังการวิวัฒน์
* การกล่าวถึงชื่อทั้งสองในเหตุการณ์เดียวกัน
* ข้อความที่แยกชื่อสกิลออกจากชื่อสถานะ
* ต้นฉบับภาษาหลักของแต่ละจุดที่ปรากฏ

### สถานะ

`รอตรวจต้นฉบับ`

## Primordial Cell

### รายการที่เกี่ยวข้อง

* ID: `skill.primordial_cell`
* อังกฤษ: `Primordial Cell`
* ไทย: `[เซลล์ดึกดำบรรพ์]`
* ประเภทปัจจุบัน: สกิล/เอฟเฟกต์
* สถานะชื่อ: ชั่วคราว

### สิ่งที่ยืนยันได้

* ชื่อนี้มีอยู่ในทะเบียนเดิม
* ประเภทเดิมถูกบันทึกเป็น `สกิล/เอฟเฟกต์`
* ยังไม่ได้ยืนยันว่าเป็นชื่อสกิลหรือชื่อผลของสกิล

### สิ่งที่ยังไม่ทราบ

* เป็นสกิลเปิดใช้หรือสกิลติดตัว
* เป็นสถานะหรือเอฟเฟกต์ที่เกิดจากสกิลอื่น
* เกี่ยวข้องกับการฟื้นฟูหรือไม่
* เกี่ยวข้องกับร่างกายหรือเซลล์อย่างไร
* มีระยะเวลา คูลดาวน์ หรือเงื่อนไขหรือไม่
* มีความสัมพันธ์กับสกิลหรือแกนรายการใด
* สามารถถูกลบล้างหรือระงับได้หรือไม่

### ข้อห้ามระหว่างรอตรวจ

* ห้ามสรุปว่าฟื้นฟูเซลล์
* ห้ามสรุปว่ารักษาบาดแผล
* ห้ามสรุปว่าเพิ่มพลังฟื้นฟู
* ห้ามสรุปว่าเป็นสกิลติดตัว
* ห้ามสรุปว่าเป็นเอฟเฟกต์ถาวร
* ห้ามกำหนดตัวเลขหรือข้อจำกัดจากชื่อ
* ห้ามเชื่อมกับ `Recovery Power` โดยไม่มีหลักฐาน

### หลักฐานที่ต้องหาเพิ่ม

* ข้อความระบบ
* คำอธิบายสกิล
* เหตุการณ์ที่ระบุชื่อพร้อมผลโดยตรง
* ข้อความที่ใช้คำว่าผล สถานะ หรือความสามารถ
* ต้นฉบับภาษาหลักของจุดที่ปรากฏครั้งแรก

### สถานะ

`รอตรวจต้นฉบับ`

# กฎการแยกสกิลออกจากเอฟเฟกต์

## ให้จัดเป็นสกิลเมื่อ

มีหลักฐานว่า:

* ผู้ใช้เปิดใช้ความสามารถ
* ระบบระบุว่าเป็นสกิล
* มีระดับสกิล
* มีเงื่อนไขการใช้
* มีคูลดาวน์
* มีทรัพยากรที่ใช้
* อยู่ในรายการสกิลของตัวละครหรือแกน

การมีชื่ออยู่ใน `สกิล.md` เพียงอย่างเดียวยังไม่เพียงพอ หากประเภทเดิมระบุว่า `สกิล/เอฟเฟกต์`

## ให้จัดเป็นเอฟเฟกต์เมื่อ

มีหลักฐานว่า:

* เกิดขึ้นหลังใช้สกิลหรือไอเทม
* เป็นสถานะที่ติดอยู่กับเป้าหมาย
* มีระยะเวลาของผล
* สามารถถูกลบล้างหรือหมดอายุ
* ระบบเรียกว่าเอฟเฟกต์ สถานะ บัฟ หรือดีบัฟ
* ไม่สามารถเปิดใช้โดยตรง

## ให้คงประเภทสกิล/เอฟเฟกต์เมื่อ

* หลักฐานยังไม่พอ
* ฉบับแปลหลายแหล่งใช้ประเภทต่างกัน
* พบเพียงชื่อโดยไม่มีคำอธิบาย
* ไม่ทราบว่าเป็นชื่อความสามารถหรือชื่อสถานะ
* อาจเป็นทั้งชื่อสกิลและชื่อผลของสกิล

# วิธีบันทึกผลที่เห็นจากเหตุการณ์

เมื่อเห็นผลของความสามารถในฉาก แต่ไม่มีคำอธิบายระบบ ให้ใช้สถานะ:

`สังเกตจากเหตุการณ์`

รูปแบบ:

```md id="5hr680"
## ข้อสังเกตจากเหตุการณ์

- สกิลหรือเอฟเฟกต์:
- ตอน:
- เหตุการณ์ก่อนใช้:
- สิ่งที่เกิดขึ้นหลังใช้:
- สิ่งที่ข้อความระบุโดยตรง:
- สิ่งที่เป็นเพียงการตีความ:
- คำอธิบายอื่นที่ยังเป็นไปได้:
- สถานะ: สังเกตจากเหตุการณ์
- หลักฐาน:
```

## ข้อห้าม

* ห้ามสรุปเหตุและผลเพียงเพราะสองเหตุการณ์เกิดติดกัน
* ห้ามสรุปคูลดาวน์จากการที่ตัวละครไม่ใช้ซ้ำ
* ห้ามสรุประยะจากตำแหน่งของตัวละครในภาพรวม
* ห้ามสรุปเปอร์เซ็นต์จากคำว่า `มาก`, `เล็กน้อย` หรือ `มหาศาล`
* ห้ามสรุปว่าเอฟเฟกต์ถาวรเพราะยังไม่เห็นหมดอายุ
* ห้ามสรุปว่าต้านทานไม่ได้เพราะศัตรูหนึ่งตัวต้านไม่สำเร็จ
* ห้ามสรุปว่าสกิลใช้ไม่ได้เพราะตัวละครหนึ่งคนไม่เลือกใช้

# การบันทึกปฏิสัมพันธ์

เมื่อสกิลสองรายการมีปฏิสัมพันธ์กัน ให้สร้างรายการแยก:

```md id="776jua"
## ปฏิสัมพันธ์ระหว่างสกิล

- สกิลต้นทาง:
- สกิลหรือเอฟเฟกต์ปลายทาง:
- ประเภทปฏิสัมพันธ์:
- ผลที่ยืนยัน:
- เงื่อนไข:
- ข้อยกเว้น:
- ช่วงตอน:
- หลักฐาน:
- สถานะ:
```

ประเภทปฏิสัมพันธ์อาจเป็น:

* เสริม
* ลด
* ลบล้าง
* ป้องกัน
* เปลี่ยนรูป
* ขยายระยะเวลา
* ลดระยะเวลา
* เปิดใช้ต่อเนื่อง
* ใช้แทนกัน
* ใช้ร่วมกันไม่ได้
* ยังไม่ทราบ

ห้ามระบุประเภทปฏิสัมพันธ์จากชื่อสกิลเพียงอย่างเดียว

# ขั้นตอนเพิ่มกลไกใหม่

1. ตรวจชื่อและ ID ใน `../สกิล.md`
2. คัดข้อความหลักฐาน
3. ระบุเลขตอนหรือแหล่งที่มา
4. แยกข้อเท็จจริงออกจากการตีความ
5. บันทึกตัวเลขและหน่วยตามต้นฉบับ
6. ระบุสิ่งที่ยังไม่ทราบ
7. ตรวจว่าขัดกับข้อมูลเดิมหรือไม่
8. กำหนดสถานะการตรวจสอบ
9. ส่งข้อมูลขัดแย้งไป `90_รอตรวจ`
10. บันทึกการเปลี่ยนแปลงสำคัญใน `CHANGELOG.md`
