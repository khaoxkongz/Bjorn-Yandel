# STGB — ข้อเสนอใหม่

## จุดประสงค์

เอกสารนี้เป็นคิวกลางสำหรับข้อมูลใหม่ที่ยังไม่ได้รับอนุมัติให้เข้าสู่ทะเบียนหลัก

ใช้กับข้อเสนอประเภท:

* ชื่อไทยใหม่
* รูปอังกฤษใหม่
* รูปสะกดอื่น
* ตัวละครใหม่
* ตัวตนหรือนามแฝงใหม่
* สถานที่ใหม่
* องค์กรหรือกลุ่มใหม่
* ตำแหน่งหรือบทบาทใหม่
* ศัพท์ระบบใหม่
* สกิลใหม่
* ไอเทมใหม่
* มอนสเตอร์หรือแกนใหม่
* ค่าสถานะใหม่
* กลไกใหม่
* พัฒนาการเสียงใหม่
* การเชื่อมข้อมูลระหว่างทะเบียน
* การเปลี่ยนสถานะข้อมูล

เอกสารนี้มีหน้าที่:

* เก็บข้อเสนอก่อนเข้าสู่ทะเบียนหลัก
* แยกข้อเสนอออกจากข้อเท็จจริงที่ยืนยันแล้ว
* ระบุหลักฐานและเหตุผล
* ตรวจรายการซ้ำ
* ตรวจผลกระทบต่อไฟล์อื่น
* ป้องกันการเพิ่มข้อมูลจากความจำหรือการคาดเดา
* บันทึกผลการอนุมัติหรือปฏิเสธ

# สถานะปัจจุบัน

ยังไม่มีข้อเสนอใหม่ที่แหล่งข้อมูลต้นทางระบุไว้อย่างชัดเจน

| รายการ | จำนวน |
| ----------- | ----: |
| ข้อเสนอเปิด | 0 |
| รอหลักฐาน | 0 |
| กำลังตรวจ | 0 |
| รออนุมัติ | 0 |
| อนุมัติแล้ว | 0 |
| ปฏิเสธแล้ว | 0 |

เมื่อพบข้อมูลใหม่ ห้ามเพิ่มเข้าสู่ทะเบียนหลักทันที เว้นแต่:

* เป็นข้อมูลที่ยืนยันได้ชัดเจน
* ไม่มีข้อขัดแย้ง
* ไม่ซ้ำกับรายการเดิม
* ระบุแหล่งและช่วงตอนได้
* ผ่านเกณฑ์ของไฟล์ประเภทนั้นแล้ว

# ขอบเขตของคิว

## ต้องเข้าคิวก่อน

รายการต่อไปนี้ต้องสร้างข้อเสนอเมื่อยังไม่มีรายการเดิม:

* ชื่อเฉพาะใหม่
* คำแปลที่ยังไม่เคยกำหนด
* ตัวละครหรือตัวตนใหม่
* สกิล ไอเทม หรือมอนสเตอร์ใหม่
* กลไกที่ต้องสร้างทะเบียนใหม่
* รูปอังกฤษใหม่ที่อาจเปลี่ยนชื่อหลัก
* การรวมสองรายการ
* การแยกรายการเดิม
* การย้ายประเภท
* การเปลี่ยนสถานะเป็นมาตรฐานหรือบังคับ
* การเปลี่ยน ID
* การเพิ่มกฎการแปลใหม่
* การเพิ่มคุณลักษณะเสียงที่อาจมีผลต่อหลายตอน

## ไม่ต้องเข้าคิวเมื่อ

* แก้คำสะกดผิดเล็กน้อยที่มีหลักฐานชัดเจน
* เพิ่มเลขตอนหรือแหล่งอ้างอิงให้ข้อมูลเดิม
* เพิ่มรูปอังกฤษอื่นที่ยืนยันว่าเป็นรายการเดียวกันและไม่กระทบชื่อ
* ปรับรูปแบบ Markdown โดยไม่เปลี่ยนข้อมูล
* เพิ่มลิงก์ข้ามไฟล์
* เพิ่มหมายเหตุเพื่ออธิบายข้อจำกัดเดิม
* ปรับสถานะจาก `รอตรวจ` เป็น `ยืนยันแล้ว` หลังปิดคิวตรวจที่มีอยู่

การแก้ดังกล่าวยังต้องบันทึกใน `CHANGELOG.md` เมื่อมีผลต่อการใช้งาน

# ความแตกต่างจากคิวอื่น

## ชื่อรอตรวจ

ใช้ `ชื่อรอตรวจ.md` เมื่อ:

* มีชื่ออยู่แล้ว
* ต้นทางระบุว่าต้องตรวจชื่อ
* ต้องตรวจรูปสะกด
* ต้องตรวจชื่อทางการ
* ต้องตรวจรูปต้นฉบับ

ใช้ไฟล์นี้เมื่อ:

* กำลังเสนอชื่อที่ยังไม่มีในทะเบียน
* กำลังเสนอชื่อไทยใหม่แทนรูปเดิม
* กำลังเสนอให้รวม แยก หรือย้ายชื่อ

## ข้อมูลขัดแย้ง

ใช้ `ข้อมูลขัดแย้ง.md` เมื่อ:

* มีข้อมูลอย่างน้อยสองชุดที่ไม่ตรงกัน
* ยังตัดสินไม่ได้ว่าชุดใดถูก
* รายการเดียวมีประเภทหรือสังกัดต่างกัน

ใช้ไฟล์นี้เมื่อ:

* มีข้อเสนอหนึ่งชุดที่ต้องประเมิน
* ยังไม่มีข้อมูลอีกชุดที่ขัดกันโดยตรง
* ต้องการเพิ่มข้อมูลใหม่เข้าสู่ระบบ

ข้อเสนอที่พบข้อมูลขัดแย้งภายหลังต้องย้ายหรือเชื่อมกับคิวข้อมูลขัดแย้ง

# สถานะข้อเสนอ

| สถานะ | ความหมาย |
| ---------------- | --------------------------------- |
| ร่าง | บันทึกข้อเสนอเบื้องต้นแล้ว |
| รอหลักฐาน | ข้อมูลยังไม่พอให้ตรวจ |
| พร้อมตรวจ | มีข้อมูลขั้นต่ำครบ |
| กำลังตรวจ | อยู่ระหว่างเปรียบเทียบกับทะเบียน |
| ต้องแก้ไข | ข้อเสนอขาดข้อมูลหรือมีปัญหา |
| รออนุมัติ | ตรวจแล้วและพร้อมตัดสิน |
| อนุมัติ | ยอมรับให้เข้าสู่ทะเบียนหลัก |
| อนุมัติบางส่วน | ยอมรับเฉพาะบางองค์ประกอบ |
| ปฏิเสธ | ไม่ยอมรับข้อเสนอ |
| ซ้ำกับรายการเดิม | พบว่ามีรายการอยู่แล้ว |
| ย้ายคิว | ต้องไปชื่อรอตรวจหรือข้อมูลขัดแย้ง |
| ถอนข้อเสนอ | ผู้เสนอหรือผู้ตรวจยกเลิก |

## กฎ

* ข้อเสนอใหม่เริ่มด้วยสถานะ `ร่าง`
* ห้ามใช้ข้อมูลจากข้อเสนอในงานแปลเสมือนเป็นมาตรฐาน
* สถานะ `รออนุมัติ` ไม่เท่ากับอนุมัติ
* ข้อเสนอที่อนุมัติแล้วต้องย้ายข้อมูลไปทะเบียนหลัก
* หลังย้ายแล้วให้เก็บผลการตัดสินในไฟล์นี้เป็นประวัติ

# ข้อเสนอชื่อใหม่

## ข้อมูลที่ต้องมี

| เขตข้อมูล | คำอธิบาย |
| ------------- | ------------------------------------ |
| อังกฤษหลัก | รูปอังกฤษที่ใช้เป็นฐาน |
| รูปอังกฤษอื่น | รูปจากแหล่งอื่นหรือการสะกดอื่น |
| ไทยเสนอ | รูปไทยที่ต้องการใช้ |
| วิธีสร้างคำ | วิธีที่ใช้สร้างรูปไทย |
| ประเภท | ตัวละคร สถานที่ สกิล หรือประเภทอื่น |
| สถานะเสนอ | ชั่วคราว มาตรฐาน ตามบริบท หรือบังคับ |
| จุดปรากฏ | ตอนหรือช่วงที่พบ |
| เหตุผล | เหตุผลเชิงภาษาและบริบท |
| ความเสี่ยง | สิ่งที่อาจคลาดเคลื่อน |
| ผลกระทบ | รายการที่ต้องแก้ตาม |

## วิธีสร้างคำที่อนุญาต

* เทียบความหมาย
* เทียบความหมายตามหน้าที่
* เทียบความหมายตามบริบท
* คำอธิบาย
* คำอธิบายตามหน้าที่
* คำยืม/ถอดเสียง
* คำยืม/คงรูป
* คำยืม+เทียบความหมาย
* คำยืม+คำอธิบาย

# การประเมินข้อเสนอ

## เกณฑ์หลัก

ข้อเสนอต้องผ่านคำถามต่อไปนี้:

1. แหล่งข้อมูลยืนยันว่ารายการมีอยู่จริงหรือไม่
2. ระบุช่วงตอนหรือจุดปรากฏได้หรือไม่
3. รายการซ้ำกับข้อมูลเดิมหรือไม่
4. ประเภทได้รับการยืนยันหรือไม่
5. รูปไทยเพิ่มความหมายที่ต้นฉบับไม่ได้ระบุหรือไม่
6. วิธีสร้างคำเหมาะกับประเภทหรือไม่
7. มีรูปอังกฤษอื่นที่ต้องรักษาหรือไม่
8. ข้อมูลขัดแย้งกับทะเบียนเดิมหรือไม่
9. ข้อเสนอมีผลย้อนหลังหรือไม่
10. ไฟล์ใดต้องปรับตาม
11. สถานะที่เสนอสูงเกินหลักฐานหรือไม่
12. สามารถตรวจย้อนกลับถึงแหล่งได้หรือไม่

## เหตุผลที่ควรส่งกลับแก้ไข

* ไม่มีหลักฐาน
* ไม่ระบุช่วงตอน
* ไม่ระบุประเภท
* ไม่มีการตรวจรายการซ้ำ
* วิธีสร้างคำไม่ชัด
* เพิ่มกลไกจากชื่อ
* รวมข้อมูลหลายประเภท
* สถานะเสนอสูงเกินไป
* ไม่ระบุผลกระทบ
* ใช้ความจำแทนแหล่งข้อมูล

# ผลการตัดสิน

## อนุมัติ

ใช้เมื่อ:

* หลักฐานครบ
* ไม่มีข้อขัดแย้งที่ยังเปิด
* ตรวจรายการซ้ำแล้ว
* ประเภทและสถานะเหมาะสม
* ระบุไฟล์ปลายทางชัดเจน

## อนุมัติบางส่วน

ใช้เมื่อ:

* ยืนยันการมีอยู่ของรายการ แต่ยังไม่ยืนยันชื่อ
* ยืนยันชื่อ แต่ยังไม่ยืนยันประเภท
* ยืนยันประเภท แต่ยังไม่ยืนยันกลไก
* ยืนยันบางรูปอังกฤษ แต่ยังต้องรักษารูปอื่น
* ยืนยันข้อมูลเฉพาะช่วง แต่ไม่ใช่แก่นถาวร

ส่วนที่ยังไม่ยืนยันต้องเข้าสู่คิวที่เหมาะสม

## ปฏิเสธ

ใช้เมื่อ:

* ไม่มีหลักฐานรองรับ
* เป็นรายการซ้ำ
* เพิ่มความหมายผิดจากต้นฉบับ
* ขัดกับข้อมูลที่มีอำนาจสูงกว่า
* เป็นการคาดเดา
* ไม่เหมาะกับโครงสร้างฐานข้อมูล
* ปัญหาได้รับการแก้ในทะเบียนอื่นแล้ว

การปฏิเสธต้องระบุเหตุผล ห้ามลบข้อเสนอโดยไม่มีประวัติ
